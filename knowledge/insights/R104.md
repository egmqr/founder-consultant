title: One customer's custom fields and heavy jobs shouldn't slow every other customer

**Summary.** Adding a column to the shared schema for one customer makes every query, migration, backup and restore carry it for everyone, and these one-offs pile up release after release. The same happens with compute: one customer's huge report competes with everyone's live traffic. Keep the core schema shared and clean, put customer-specific fields in a scoped extension store, run heavy per-customer work in separate queues or workers, and keep core migrations backward compatible so no single customer's change forces downtime for all.

**Takeaways**
- Customer-specific fields live in a scoped extension table or document field, not new shared columns
- Heavy or custom per-customer workloads run on queues or workers with per-customer limits
- Core schema migrations are backward compatible; extension changes run per customer
