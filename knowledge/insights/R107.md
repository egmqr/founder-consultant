title: Throttle sign-in and bots at the edge, before traffic reaches your servers
areas: [SEC]
checks: [SEC-27, SEC-10]
---
**Summary.** Having a network edge or firewall service in front of an app does nothing until it is configured. Credential-stuffing bots, scrapers and scanners pass straight through, burning compute and raising the bill. Set per-IP rate limits at the edge on sign-in, sign-up, password reset and code-verification routes that block or challenge above a threshold. Apply bot rules to high-value pages (pricing, checkout, API docs, public galleries or listings) so automated scraping is challenged before it reaches the origin. Add rule sets for known attack patterns (injection, cross-site scripting, path traversal) in blocking mode.

**Takeaways**
- Auth routes have per-IP rate limits enforced at the edge, not only in app code
- High-value public routes have bot detection or challenge rules
- Known attack-pattern rules run in blocking mode at the edge
- The origin should only accept traffic from the edge, or the limits are bypassable
