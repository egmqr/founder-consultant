title: The model that wrote the code should not be its only reviewer
areas: [HAR, CHG]
checks: [HAR-13]
---
**Summary.** Each model and coding tool has habits and blind spots it can't see in its own output, and a tool asked to review its own work tends to defend it. Run security and correctness reviews on a different model or tool than the one that generated the code, frame the security review as an attack, and for critical modules compare a second independent implementation of the same spec: where the two differ is where hidden assumptions live.

**Takeaways**
- Generator and reviewer are different models
- Security reviews are framed as penetration tests
- Differences between two builds of one spec expose silent design decisions
