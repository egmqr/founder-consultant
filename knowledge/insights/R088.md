title: The browser never sets the price
areas: [AUTHZ]
checks: [AUTHZ-19]
---
**Summary.** When the front end sends an amount to the checkout call, anyone can edit it and the payment provider will charge whatever arrives. The client should send only a product or plan ID; the server looks up the price, preferably as a price object stored at the payment provider, and creates the checkout itself. A success page is not proof of payment either: access is granted only after a verified provider event confirms the payment and its amount matches the product.

**Takeaways**
- Client sends what to buy, the server decides what it costs
- Prefer provider-side price objects over raw amounts in code
- Grant access from a verified payment event, never from a redirect
