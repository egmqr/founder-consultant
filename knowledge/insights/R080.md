title: Signed webhooks still arrive twice
areas: [AUTHZ]
checks: [AUTHZ-15]
---
**Summary.** Providers retry any webhook that times out or errors, so a perfectly valid, signed event can reach the handler more than once. A signature only proves who sent it; it says nothing about whether you already acted on it. Without an idempotency step, one slow response turns into a double charge, a duplicate account or a second email. Record the event ID before running the handler, skip IDs already recorded, reject events older than a fixed window (for example a day), and answer duplicates with success so the provider stops retrying.

**Takeaways**
- Signature proves the sender; idempotency proves you acted once
- Record the event ID first, then process, so a crash mid-handler doesn't run it again on retry
- A timestamp window bounds storage and kills replays of old captured events
- Return success for duplicates; an error invites more retries
