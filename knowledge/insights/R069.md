title: Watch who still maintains your infrastructure
areas: [SEC]
checks: [SEC-12, SEC-5]
---
**Summary.** When a core open-source component changes its license and the community forks it, security fixes and review often move to the fork, and the original may patch slower or differently. AI setups install whatever the tutorials name and never revisit that choice. Review critical infrastructure components for maintenance health and license changes, keep each behind one adapter so switching provider is a config change, and pin every infrastructure version so a deploy never pulls an unplanned upgrade.

**Takeaways**
- Recheck where security patches actually land after a fork
- Wrap infrastructure clients in one adapter, not calls everywhere
- Pin infrastructure versions and update on a schedule
