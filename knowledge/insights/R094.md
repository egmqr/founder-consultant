---
id: R094
date: 2026-11-25
title: Mobile apps must refuse untrusted connections and keep tokens in secure storage
areas: [SEC]
checks: [SEC-22]
---
**Summary.** A mobile app talks to its server over networks the user doesn't control. If it allows plain HTTP or accepts any certificate, anyone on the same Wi-Fi can read or alter sign-ins and tokens. If it stores tokens in plain preferences or files, other apps, backups or anyone holding the device can lift them. Allow only HTTPS with normal certificate checks (pin certificates or keys for the app's own API where the rotation plan supports it) and keep tokens and credentials in the platform's secure storage.

**Takeaways**
- No cleartext traffic allowed in the app's network config
- No code that trusts all certificates or skips hostname checks
- Pinning, where used, has a backup pin and a rotation plan
- Tokens and credentials live in Keychain, Keystore-backed storage or the OS credential vault, never plain preferences or files
