title: Allow only listed origins in CORS settings
areas: [AUTHZ]
checks: [AUTHZ-7]
---
**Summary.** AI-generated APIs often answer cross-origin checks with a wildcard, which lets any web page read responses. Paired with credential support, a hostile page can make signed-in requests with the user's cookies and read the full private response. Echoing back whatever Origin header arrives is just as open and slips past scanners that only flag wildcards. Replace these with a fixed allowlist of the product's own domains, and permit credentials only when the incoming origin matches that list.

**Takeaways**
- No wildcard origin on APIs that return private data
- Credentials allowed only for allowlisted origins
- Never reflect the Origin header without checking it
- State-changing cookie routes also check a verification token or the Origin header, and each route allows only the methods and headers it uses
