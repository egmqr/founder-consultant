title: Production errors should reveal nothing
areas: [SEC, EVI]
checks: [SEC-20]
---
**Summary.** Detailed errors help during development, but in production a stack trace, failed query, file path, database name or package version hands an attacker a map, often to someone who just followed a broken link. Return generic messages in production, send the full detail (stack, request context, user) to central searchable logs, and give every common error code a custom page that offers a next step without exposing internals.

**Takeaways**
- Error detail goes to logs, never to the screen or the response body
- Error handling depends on environment and defaults to quiet
- Test with a broken link and a malformed request in production
