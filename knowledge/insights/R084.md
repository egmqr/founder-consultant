title: State stops forgery, PKCE stops interception
areas: [AUTHZ]
checks: [AUTHZ-17]
---
**Summary.** In an OAuth sign-in, the state parameter protects against forged login requests, but the authorization code still travels in a URL that can be intercepted on shared networks, by other apps on a mobile device or through a compromised browser. Whoever holds that code can exchange it for a session. PKCE closes the gap: the app creates a random verifier before the redirect, sends only its hash, and must present the original verifier to exchange the code, so a stolen code is useless.

**Takeaways**
- Use both state and PKCE on every OAuth flow, web and mobile
- The verifier never appears in a URL
- Test that a code exchange without the right verifier fails
