title: Treat the cache like the database it guards
areas: [SEC]
checks: [SEC-13]
---
**Summary.** AI setups often add a hosted key-value cache for sessions, caching and rate limits, then leave its default connection open: one credential that can run every command from any network. Whoever holds that connection string can read every active session token and become any user, wipe the cache, or rewrite its config, without cracking anything. Give the app a restricted cache user limited to the commands it actually uses, deny the rest, and accept connections only from the deployment's own network.

**Takeaways**
- A session store is a first-class database, not a side cache
- The app's cache user runs only the commands the app calls
- Cache connections come only from the deployment's network range
