title: Treat uptime as a budget per critical endpoint, and alert on how fast it burns
areas: [EVI]
checks: [EVI-6]
---
**Summary.** A status page that says everything is up while customers see errors means monitoring measures the wrong thing. Give each revenue-critical endpoint (payments, sign-in, the core action) its own allowed failure rate over a rolling window, set from business impact rather than infrastructure defaults. Alert on burn rate, the speed at which that allowance is being used, so a trend fires before a breach. When the allowance is exhausted, pause feature releases and fix reliability. Record each incident in affected users, failed transactions and lost revenue, so a checkout failure outranks a documentation-page failure.

**Takeaways**
- Error budgets per critical endpoint over a rolling window, not one global uptime figure
- Burn-rate alerts fire when projected use would exhaust the budget before the window resets
- Exhausted budget pauses feature releases until reliability recovers
- Incidents are sized in users, transactions and revenue, not only status codes
