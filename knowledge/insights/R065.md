title: A reverse proxy is not a firewall
areas: [SEC]
checks: [SEC-10]
---
**Summary.** AI-built server setups often put a reverse proxy in front of the app and stop once traffic routes and TLS terminates. That proxy forwards requests without inspecting them, so injection, cross-site scripting and path-traversal attempts reach the app untouched. Add a web application firewall with a maintained rule set in blocking mode on every route that takes user input, ban addresses that keep tripping it, and alert when blocked requests spike, since a spike means someone is probing right now.

**Takeaways**
- Routing traffic is not inspecting it
- Run a maintained WAF rule set in blocking mode on input routes
- Ban repeat offenders automatically, with escalating durations
- Alert on spikes in blocks and bans, not just log them
