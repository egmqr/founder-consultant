title: A central auth layer is not the only check
areas: [AUTHZ]
checks: [AUTHZ-13, AUTHZ-1]
---
**Summary.** Putting the login check in one middleware or gateway file feels like every route is covered. In practice the route matcher can leave out API paths, trailing slashes, double-encoded characters or alternate prefixes can slip past it, and an edge check often only looks for a cookie's presence without validating it. Treat the central layer as a convenience: confirm it matches every protected path including variants, and keep a real server-side authorization check in each handler. Make protected the default, so a handler added later starts from an authenticated base instead of from nothing.

**Takeaways**
- The matcher covers API routes as well as pages
- Path variants (trailing slash, encoding, prefixes) are tested against it
- Each handler validates the session itself, not only the edge layer
- New handlers start from a protected base, so public is the explicit choice
