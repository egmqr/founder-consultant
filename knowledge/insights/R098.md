title: Vet every package before it's installed, including the ones an AI suggests
areas: [SEC]
checks: [SEC-24]
---
**Summary.** Every dependency is someone else's code running with full access to the app's environment, and one app can pull in hundreds of transitive packages. Look-alike package names and hijacked maintainer accounts are used to ship code that reads environment variables and sends secrets away at startup; AI assistants can suggest such names without checking. Vet new packages before installing, watch the whole tree for risky signals, keep secrets away from code that doesn't need them, and have CI install only what the lockfile and its checksums say.

**Takeaways**
- Check each new package's exact name, age, download count, maintainer and install scripts before adding it
- Audit the full tree (not just direct dependencies) for recent maintainer changes, very low usage and install-time scripts
- Disable install scripts by default and allow them per package
- CI installs strictly from the lockfile and fails on any checksum mismatch
- Pass each module only the secrets it needs instead of the whole environment
