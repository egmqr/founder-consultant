title: Decoding a token is not verifying it
areas: [AUTHZ]
checks: [AUTHZ-16]
---
**Summary.** A signed token (such as a JWT) is just encoded text until its signature is checked. Code that decodes the token and reads a role claim without verification lets any user edit the claim, re-encode it and become an admin, with no alert. Verify the signature against the provider's published keys on every request, then reject tokens that are expired, from the wrong issuer or meant for another audience. Use the auth provider's server SDK rather than hand-parsing, since it also handles key rotation.

**Takeaways**
- Verify the seal before reading any claim
- Expiry, issuer and audience are checked every time
- Hand-rolled token parsing works for honest users and fails for attackers
