title: Raw queries drop the ORM's protection
areas: [SEC]
checks: [SEC-17, SEC-18]
---
**Summary.** An ORM or query builder keeps user input out of the command text, but the moment a query gets complicated (a search, a custom join, a dynamic sort), generated code often falls back to a raw query built by string concatenation. That one spot turns a search box into a direct line to every table. Find every raw query in the codebase, make each one pass user values as bound parameters, allow-list anything that can't be a parameter (sort columns, directions), and constrain input type and length before it reaches the data layer.

**Takeaways**
- The ORM is safe; the escape hatch is where injection lives
- Search the codebase for every raw query; you can't fix what you haven't counted
- Identifiers like sort columns come from an allow-list, never from the request
