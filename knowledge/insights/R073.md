title: Issue a new session when identity changes
areas: [AUTHZ]
checks: [AUTHZ-10]
---
**Summary.** Many session setups create an ID on the first visit and keep it after login. An attacker who plants a known session ID on a victim (through a crafted link, say) then shares the victim's session the moment they sign in: session fixation. The same flaw applies to any privilege change, such as a plan upgrade or a viewer promoted to admin. Regenerate the session ID on login and on every privilege change, and set Secure, HttpOnly and SameSite on every session cookie so it can't travel over plain HTTP, be read by scripts, or ride along on cross-site requests.

**Takeaways**
- New session ID after login and after every role or plan change
- Session cookies are Secure, HttpOnly and SameSite
- A pre-login session ID must never be valid after login
