title: Stop other sites from framing your app
areas: [SEC]
checks: [SEC-14]
---
**Summary.** If an app sends no anti-framing header, any site can load it in an invisible frame and lay its own bait on top, so a signed-in user's click lands on a real purchase, permission grant or password change in your app (clickjacking). Send both the legacy and the modern header on every response: X-Frame-Options DENY and a Content-Security-Policy frame-ancestors rule. When one feature genuinely needs embedding, allow framing only on that route instead of dropping the protection everywhere.

**Takeaways**
- Every response carries X-Frame-Options and CSP frame-ancestors
- Older browsers need the legacy header, so send both
- Allow framing per route, only where an embed truly needs it
