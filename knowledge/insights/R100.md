title: A server or agent that fetches user-supplied URLs needs an outbound boundary
areas: [SEC]
checks: [SEC-26]
---
**Summary.** When a server or AI agent fetches a URL a user gave it, the request leaves from inside your network with your server's access. Without a boundary, an attacker can point it at internal services, admin panels or the cloud metadata endpoint that hands out credentials, and read the answer. A one-time domain check is not enough: redirects and DNS tricks pass the check and then land on an internal address. Differing error messages also leak which internal hosts exist.

**Takeaways**
- Outbound fetches of user-supplied URLs go only to an allowlist of external domains; private, loopback, link-local and metadata addresses are blocked
- Resolve the host once, check the resolved address, connect to that same address, and recheck on every redirect
- Every failed fetch returns the same generic error; the detail goes to internal logs
- The same rules apply to AI agent tools that browse or fetch on a user's behalf
