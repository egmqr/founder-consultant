id: R074
date: 2026-11-21
title: Validate every redirect in the sign-in flow
areas: [AUTHZ]
checks: [AUTHZ-11, AUTHZ-9]
---
**Summary.** "Return to where you were" after login usually reads its target from a URL parameter. If the server doesn't validate it, an attacker sends a link to your real login page that ends on their phishing page, right after the user has just signed in for real. Simple string checks are bypassed by protocol-relative paths, backslashes and encoded characters that browsers resolve differently from the validator. Parse each redirect target the way the browser will and accept only your own origins, and apply the same rule to logout and every other redirect in the auth flow.

**Takeaways**
- Redirect targets are parsed, then checked against own origins
- Reject protocol-relative, backslash and encoded variants
- Logout and error redirects get the same check as login
