title: Mobile deep links can be hijacked unless they are verified
areas: [AUTHZ]
checks: [AUTHZ-20]
---
**Summary.** A web app shipped inside a mobile shell loses the browser's protections, and custom URL schemes are one of the gaps: any app on the device can register the same scheme and receive sign-in callbacks, password-reset links or payment confirmations meant for yours. Verified links tied to a domain you control (universal links, app links) can't be claimed by another app, and every incoming link still needs its parameters validated before the app acts on it.

**Takeaways**
- Sign-in, password-reset and payment callbacks use verified domain links, not custom schemes
- Sign-in through an external browser uses PKCE and a state value so an intercepted code is useless
- Every incoming deep link is parsed and validated (expected host, path and parameters) before any action
- Secrets in mobile shells belong in platform secure storage, not web storage (see the mobile transport check)
