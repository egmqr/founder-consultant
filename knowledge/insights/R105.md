title: Serve every customer from one codebase with per-customer configuration, not forks

**Summary.** Copying the codebase or opening a branch per customer to meet their requests turns one product into many that share a name: every fix must be repeated, nobody remembers which customer runs what, and updates stop reaching everyone. Keep one codebase and one deployment. Resolve the customer on every request before business logic runs, load a shared base configuration plus that customer's explicit overrides, and switch behaviour with flags scoped to the customer. Before building any customer-specific feature, estimate what it costs to keep (build, extra test surface, upkeep each release) against what that customer pays, prefer a configuration change over a code branch, and when several customers ask for the same thing, make it a product feature.

**Takeaways**
- One codebase and deployment serve all customers; no per-customer branches, forks or deployments
- Customer context is resolved at the request boundary (subdomain, header or token claim) before any logic
- Base configuration with per-customer overrides merged at runtime; flags are scoped by customer ID
- Custom work gets a written upkeep-cost estimate first; repeated requests become product features
