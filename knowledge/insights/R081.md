title: Browser validation is not a security control
areas: [SEC]
checks: [SEC-17]
---
**Summary.** Form validation in the browser only helps honest users; anyone can call the API directly with empty strings, negative prices or extra fields. When the server trusts the raw request body, whatever arrives lands in the database, including fields the form never had, such as a role flag or a price override. Run the same schema on the server for every route, reject unknown fields instead of passing the whole body through, constrain every value to its expected type and length, and test each route by sending requests without the form.

**Takeaways**
- Client validation is UX; server validation is security
- An unexpected field is rejected, never stored
- Reject bad input rather than trying to clean it
- Every route gets tested with a hand-crafted request, no form involved
- Privileged fields change only through separate admin routes; tests send them to every user route
